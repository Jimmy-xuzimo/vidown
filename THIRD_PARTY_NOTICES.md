Installed npm components retain their license files. The Windows application directory retains Electron's LICENSE and LICENSES.chromium.html. Tool preparation copies native tool licenses and all production npm component notices into the tool directory and records binary SHA-256 values. Source-built extractor packages retain Python dependency license texts. Local Windows development can still use Gyan 9.0.2; those upstream binary artifacts are not uploaded by the public release workflow.

The Windows webpage host uses the user's installed Microsoft Evergreen WebView2 runtime; that browser runtime is not bundled. Electron remains the local application shell and network transport for protocol downloads. The native host is self-contained, so users do not need a separate .NET installation. Its pinned runtime versions and associated notices are retained in `webview2-host`.

Public release packages are built by `.github/workflows/release.yml` on native Windows, macOS and Linux runners. Each platform publishes a corresponding-source archive with the actual FFmpeg/x264 trees, Python and Python dependency sources, source revisions, build recipes and configuration. The application source is available at the same release tag. Exact dependency inventories and SHA-256 values accompany the artifacts. See [build instructions](docs/BUILDING.md). Electron retains its LICENSE / Chromium notices; the Windows native host retains WebView2 and .NET notices. macOS uses ad-hoc signatures only; Windows binaries are unsigned. The application must not describe the entire binary bundle as MIT.
