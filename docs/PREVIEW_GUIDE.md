# Windows 预览版试用

当前是 M0 实验预览。已验证的规格和限制以 [验证记录](VALIDATION.md) 为准；[检查点](STATUS.md) 列出本轮结果。

## 启动与保存位置

先正常退出旧版，再双击 `release/Vidown Preview 1.0.0-alpha.3.exe`。便携 EXE 自带浏览器和下载工具，首次启动会自解压；无需安装 Python、Node.js 或 FFmpeg。包目前未签名，文件 SHA-256 与运行时代码版本见 [构建记录](validation/windows-preview-artifact.json)。新版使用原有用户档案，不需要清理旧数据。

先在「设置与账号」选择保存目录。浏览器登录和任务数据库按当前 Windows 用户保存，不随 EXE 自动搬迁；开发验收使用的隔离登录档案也不会自动导入普通启动的应用。

浏览器区域随窗口伸缩，工具栏提供 25%–200% 网页缩放和「适应宽度」，也支持 Ctrl/Cmd＋加减号、Ctrl/Cmd＋0 和鼠标滚轮缩放。各网站手动缩放比例会保留；收起资源栏可以给网页更多空间。

网站的持久 Cookie 由 Chromium 按其原有效期保存。临时会话 Cookie 在系统安全存储可用时加密保留最多 7 天；原生 Cookie 更新或网站主动注销时不会用旧备份覆盖。网站可使登录提前失效。「清除内置浏览器登录」会同时清除本地登录数据与备份。

## 下载 B 站高规格内容

1. 在「浏览器探测」输入视频页面，登录自己的账号并播放。需要大会员的规格以账号实际返回的格式为准。
2. 点击「提取当前页面」，或直接回下载工作台粘贴视频链接。两个入口使用同一浏览器登录会话。登录前已提取过的结果需要重新探测。
3. 在「视频轨道」分别查看分辨率、编码、帧率、HDR10 或杜比视界；在「音频轨道」选择 AAC、FLAC 或杜比音轨。Hi-Res 和杜比多声道是不同选择。没有返回的规格不会凭标题补出。
4. 使用默认保留源规格的输出策略，点击「加入下载队列」。完成后在「下载记录」打开文件位置。

杜比视界和视频＋FLAC 组合使用 MKV。8K SDR 与 4K HDR10 可以是同一视频中的不同轨道；选择 8K 不代表同时得到 HDR。浏览器预览、显示器能力与下载保存的源规格分别判断。

单独保存音乐时，将「视频轨道」设为「仅下载音频」，再选择音轨；原始 FLAC 会输出 `.flac`。本版拒绝未经明确色彩转换的 HDR／杜比兼容导出。

## X 和通用流媒体

公开 X 帖子可先在下载工作台粘贴链接并点击「探测资源」。需要登录的页面可在内置浏览器打开；本轮仅验证了公开 X 内容，登录 X 仍待验收。

通用网站在浏览器内登录并播放后，从资源侧栏优先解析 HLS／DASH 清单，再选择视频和音频。`blob:` 本身不是下载地址，需要等待其背后的实际媒体请求。资源侧栏无结果或提取失败时，保留错误信息，在「设置与账号」导出脱敏诊断。

## 暂停、恢复与错误

同一次应用会话中的暂停会停止实际传输；继续时验证清单或源文件身份。正常退出会停止下载组件。重启后的任务保留记录，但需要重新粘贴链接探测并新建任务；此版本不自动恢复过期授权。取消和完成的任务不能原地重新入队。

“正在下载”“合并轨道”“验证成品”是不同阶段，未验证通过不会标记完成。页面可播放但提取失败时，检查具体错误及账号实际权限；DRM、试看、源未提供目标规格与网络失败需要分别判断。可以保留错误和下载记录，稍后再处理需要账号或样本的项目。

Telegram 统一在浏览器访问官方 Web A 或 Web K 并登录，再回工作台粘贴具体 t.me 消息链接；应用沿用已打开的客户端及其登录状态。Web K（含 https://webk.telegram.org/）打开目标视频后，还可使用“提取当前页面”或解析对应资源。应用显示网页保存选项并调用允许的下载操作，不重放站内播放地址。真实账号和私有消息完整下载尚待验收；找不到消息、网页未提供下载或结构变化时会明确失败，不将网页预览尺寸作为原文件画质。网页没有保存权限时明确停止；如果网页另要求选择保存档位，按照提示在网页下载菜单中手动选择，实际保存仍会进入任务。网页准备文件时可能只有等待状态，取消后不会保存迟到文件；网页内部的缓存和预取由网页管理。网页发起的文件保存不受引擎并发设置控制。没有网站专属登录入口，也无需 API ID／Hash。Chrome／Edge 扩展、自动刷新签名和正式跨平台安装包仍在路线图中。
